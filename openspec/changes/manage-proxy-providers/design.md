## Context

此前对话已确认原生 YAML 持久化，并关注配置修改是否会中断已有连接。本轮要求在面板完成提供商订阅的添加、删除、禁用、启用和链接编辑。

当前提供商列表来自 GET /providers/proxies，模型没有订阅 URL 或禁用状态；没有运行态提供商时，整个区域被隐藏。当前合并逻辑在新列表为空时保留旧节点，新增停用功能后需要区分有效空结果、接口不可用和过期响应。

上一会话使用的 default_limit_manual.yaml 包含 fm / pq / cx 三个 HTTP 提供商、35 个代理组，其中 17 个使用 include-all；当前没有显式 use 列表。这里仅检查配置结构，未修改配置或访问运行中的核心。

mihomo v1.19.31 的提供商 schema 没有 enabled / disabled 字段，PUT /providers/proxies/{name} 只刷新既有源。提供商解析拒绝过滤后零节点。完整配置应用会重新初始化保留的提供商，其中 HTTP / file 提供商的初始化代码会关闭 ProviderChains 中包含同名提供商的连接。详细源码依据见 research.md。

## Goals / Non-Goals

Goals：通过现有 Proxy 面板管理原生提供商；停用可恢复，节点在核心和面板中一致退出新连接候选；核心停止时可编辑；保留原生字段、配置顺序及可靠的冲突保护；如实呈现应用和连接影响。

Non-Goals：App 私有订阅库、启动生成另一份配置、自动重合并整份订阅、维护 mihomo Fork、通用订阅转换平台、远程文件管理服务、任意代理组重构、提供商重命名和批量拖拽排序。

## Candidates

### A. Suspend the native provider — recommended

禁用项退出有效 proxy-providers 定义，原定义保存在同一主配置的可读注释块。受管理注释保存受影响组的逻辑 use 顺序与提供商顺序，原位写回生效的 use；include-all 及 include-all-providers 按核心原生逻辑包含仍有效的定义。恢复发生在用户点击启用时，结果直接写回原生配置。

提供商管理列表仍展示禁用项，便于启用、编辑链接或永久删除。当前有效配置不再包含该提供商，因此新连接候选、后续订阅更新和健康检查应随核心应用退出，具体停止及在途请求行为须实测。

优点是禁用结果可以由裸 mihomo 直接执行，并覆盖自动引入提供商的代理组。主要成本是注释块、引用恢复、复杂 YAML、空组和配置应用的处理。

### B. Hide provider nodes in the panel

按配置及提供商身份记录界面隐藏偏好，过滤列表和节点选择器。没有配置重载，核心仍可能自动选择这些节点，订阅更新和健康检查继续运行；脱离 App 后全部节点继续可用。

适用于用户仅希望整理面板的情况。该方案需要明确使用“隐藏 / 显示”的界面含义，并处理多个提供商拥有同名节点的归属；不作为本草案推荐的禁用语义。

### Rejected shortcuts

- 给提供商添加 disabled: true：目标核心没有这个字段，不能作为停用依据。
- 将 exclude-filter 改为匹配全部节点：目标核心会拒绝零节点结果，刷新失败还可能保留旧节点。
- 仅删除 use 列表中的名称：include-all-providers 会覆盖 use，无法覆盖用户目前的自动引入组。

## Decisions

实现采用已确认的方案 A。

### 1. Native document and identity

增加 NativeProxyProviderDocument / Entry，保留规范化配置路径、原始文件快照、提供商名称、完整原生定义、源范围、禁用注释块和代理组引用。订阅 URL、header、override、filter、exclude-filter、健康检查和未知字段来自文件，运行态摘要只补充节点、流量、更新时间及应用状态。

身份包含配置路径和提供商名称；节点归属使用提供商与节点名称的组合。当前文件未被核心应用时，不用运行态的同名提供商冒充该文件的实际状态。运行基线应包含最近成功应用的原生配置快照，不能只比较规则列表或提供商名称。

### 2. Recoverable disable and enable

普通块 YAML 优先使用源范围局部修改。禁用时将完整定义与引用顺序保存在同一文件顶部的成对注释内：

```yaml
# clashbar:disabled-proxy-providers begin
# definitions:
#   fm:
#     type: http
#     url: https://example.com/subscription
# groups:
#   Custom: [fm, pq]
# order: [fm, pq]
# clashbar:disabled-proxy-providers end
proxy-providers:
  pq:
    type: http
    url: https://example.com/another-subscription
proxy-groups:
  - {name: Custom, type: select, use: [pq]}
```

只识别 App 明确写入的成对标记，不把用户普通注释猜测成禁用项。显式引用按保存的逻辑顺序恢复。为了让无来源组通过核心校验而增加的临时静态成员，在重新启用并恢复来源时清理。启用只恢复仍能可靠对应的定义及引用；名称冲突、组被删除或引用上下文无法对应时停止恢复并展示冲突，不覆盖期间的外部编辑。

流式根映射、锚点、别名和合并映射需要先解析完整语义。必要时生成等价的普通 YAML，并保留禁用数据和未知字段；无法证明等价时拒绝保存。禁用信息是可读原生配置注释，不存入 UserDefaults 或私有文件，不在启动时合并。

禁用状态下编辑链接仍保持禁用，仅改变注释中的定义，当前核心无需为纯注释修改重载。启用后再对有效源执行加载与应用验证。

### 3. Group dependencies and empty groups

保留现有 include-all、include-all-providers、include-all-proxies、过滤条件和成员顺序。新增有效提供商会自然加入自动引入组；对显式 use 组提供可选绑定，并预览实际会接纳节点的组。

禁用和删除前列出显式引用、自动引入组及当前选择受影响情况。组的来源被移除，或按过滤条件已经没有可用成员时，要求选择有效备用或明确的回退策略；不依赖未经用户选择的空组默认回退。最终候选仍由核心检查。通用的代理组编辑不扩展到本次范围。

永久删除移除有效定义或禁用注释块，以及指向该项的受管理恢复引用。共享文件、其他提供商源、用户备份及无关缓存不随删除操作一起移除。

### 4. Panel and editor

提供商行以暂停 / 播放图标分别表示点击后禁用 / 重新启用，保留操作提示和辅助功能标签。空组选择器展示内置策略 DIRECT（不经过代理）和 REJECT（拒绝连接），不预选，不把占位提示当作第三种策略。

提供商区域在本地配置可管理时始终显示，标题提供“添加订阅”和管理入口。列表整合原生有效项、禁用项与可对应的运行摘要，展示已启用 / 已禁用 / 未应用 / 未运行 / 加载失败状态。

每行保留刷新，并增加启用开关和编辑 / 删除菜单。禁用项卡片保留，不展示为可用节点；禁用、删除和配置切换清理对应节点缓存，取消或丢弃旧请求。新 provider 摘要中的空节点列表不能被旧节点无条件替代。

添加表单以名称和 HTTP(S) 链接为必填，更新间隔、健康检查与组绑定折叠为可选项。名称必须唯一并排除核心保留名。已有 file / inline 定义可展示和共用生命周期操作，链接编辑仅适用于 HTTP 提供商；已有项名称在本轮保持稳定。

编辑链接保留查询参数、大小写敏感内容和其他未修改原生字段。面板列表不铺开完整带凭据链接，日志避免输出完整 URL 或授权头。保存和加载进度有明确反馈；删除展示影响并确认。

### 5. Subscription loading and cache provenance

目标是 mihomo 可读取的节点订阅。新增或修改链接需校验输入，并实际检查订阅是否能产生有效节点；只有代理组 / 规则集的完整配置不能被误报为已成功添加节点源。

mihomo -t 的配置结构校验不能代替 HTTP 提供商内容加载验证。候选源在独立目录的 mihomo 进程加载；保留已有源的缓存用于组过滤，新 URL 使用独立空路径，并要求下载生成缓存，避免旧文件或内嵌备用节点掩盖加载失败；验证失败保留旧文件和已用节点。

URL 变化优先使用独立的新缓存路径，并将该路径写入原生定义；路径变化列入保存差异，旧缓存用于恢复。最终节点加载结果必须来自新源。更新链接后的订阅信息、延迟历史和节点状态重新读取，过期请求不能写回新版本。

### 6. Save, apply and recovery

抽取或扩展现有通用配置事务，提供商保存独立核验其原生快照与运行基线，不直接套用只检查规则对应关系的 commitRoutingRuleEdit。配置切换、核心启停、订阅覆盖、设置写入和提供商刷新协调串行化；核心自身对缓存的写入也需纳入缓存设计。

保存顺序：候选构造与差异、配置和新源验证、再次检查文件快照、备份、原子写入、目录监控自身写入确认、应用、读取结果并核验。当前运行配置通过 PUT /configs?force=false 应用，合并最新运行模式、端口、IPv6、TUN 和进程识别等设置；停止核心或编辑非运行配置时只保存文件并显示未应用。

提供商加载失败只记录日志的核心行为不能被 HTTP 成功状态掩盖。应用后核验提供商与代理组结果，失败恢复文件和运行态；恢复中发生外部修改时保留外部内容，并提供备份及具体错误。

同进程应用保持 PID 作为验收目标，但目标核心会重新初始化 HTTP / file 提供商并可能关闭关联连接，影响可超出正在编辑的一家订阅。界面需呈现这个影响，采用一次事务完成一次管理操作；不承诺提供商连接持续传输，不主动额外清空连接。

### 7. Local, remote and subscription overwrite

本地主配置是持久化来源。远程 REST API 无增删提供商和修改源链接的能力，首版远程保留只读统计和已有刷新功能，不写本机文件来改变远端。

节点订阅更新只更新原生缓存，不覆盖主配置里的有效 / 禁用定义。整份配置订阅覆盖更新可能删除新增项、禁用注释及 use 恢复位置，编辑器和说明明确提示；不会在更新后自动重新合并，继续推荐稳定本地主配置搭配 proxy-providers。

## Risks / Trade-offs

主要风险是当前核心的提供商连接关闭行为、受管理注释与复杂 YAML 的恢复、空组回退、新 URL 被旧缓存掩盖，以及晚到请求重新显示已禁用节点。当前源码结论需通过独立真实核心实验确认影响范围；普通规则编辑的既有 TCP 实测不能替代此项验收。

如果用户要求禁用操作完全不影响已有连接，需要重新讨论方案 B 或另行评估核心生命周期支持。不会把 PID 不变作为连接不中断的证据。

## Validation

单元与文件测试覆盖字段保留、块 / 流式 / 锚点 / 合并 / CRLF、定义及 use 往返、同名冲突、空组、外部修改、备份恢复、不同源同名节点、禁用状态下改链接及晚到请求。

视图模型覆盖无提供商 / 停止核心仍可添加、非运行文件保存、远程限制、有效空节点与接口失败区分、配置切换和加载失败反馈。

真实核心仅使用独立进程、临时工作目录、loopback 订阅 / SOCKS / 回显服务及临时端口。验证节点从自动 / 显式引用组退出及恢复、禁用后更新行为、URL 新旧源与缓存来源、失败恢复、运行设置和 PID。必须建立经提供商节点的长连接并核对 providerChains，分别记录被禁用提供商和仍有效提供商的连接结果。
