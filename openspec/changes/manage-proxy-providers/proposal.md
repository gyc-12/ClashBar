## Why

用户希望直接在 Proxy 面板管理代理提供商订阅：快速添加、删除、启用、禁用和更换订阅链接。禁用后，该提供商的节点暂时退出节点列表，同时保留再次启用所需的信息。

现有提供商区域只有运行态统计和刷新按钮，既无法读取订阅 URL，也无法管理已禁用项。此前已确认 ClashBar 保持原生 mihomo 面板定位，持久化配置可以脱离 App 运行；本次继续沿用这一约定。

用户已确认采用 design.md 中的方案 A，禁用后从核心的新连接候选中移除提供商，并提示应用时的连接影响。

## What Changes

- 提供商区域增加添加入口、启用开关和编辑 / 删除操作；没有提供商或核心停止时仍保留管理入口。
- 从当前本地主配置读取原生定义，结合核心摘要展示运行状态；禁用项保留在管理列表中。
- HTTP(S) 订阅支持名称、链接及可选更新 / 健康检查参数；编辑已有项保留未修改的原生字段。
- 禁用时将提供商定义保存为同一 YAML 内可读的受管理注释块，并协调显式 use 引用；启用恢复对应定义和引用。
- 保留 include-all / include-all-providers 的原生语义，预览受影响代理组，对空组、冲突和无法可靠恢复的情况给出明确处理。
- 复用配置校验、备份、原子写入和失败恢复；新增订阅加载验证与缓存来源核验。
- 运行中的当前配置通过同进程重载应用，明确说明提供商初始化可能关闭关联连接；不沿用普通规则测试的连接连续性结论。
- 维护中英文文本、原生配置使用说明、自动化及独立核心验收。

## Capabilities

### New Capabilities
- `proxy-provider-management`: 原生代理提供商订阅的管理、可恢复停用与运行态同步。

### Modified Capabilities

无。现有刷新接口继续用于更新已存在的提供商内容。

## Impact

Provider 模型、ProxyStore、ProxyTabView、ProxyProvidersAndGroupsView、提供商刷新与轮询、配置事务及监控链路。增加原生提供商文档 / 编辑服务和编辑器，不引入 App 私有提供商数据库或启动合并层。远程控制器首版保留运行态查看与已有刷新能力。
