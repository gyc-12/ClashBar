## Context

ClashBar 是原生 mihomo 面板。已有原生规则编辑与代理延迟曲线，连接模型尚未读取完整元数据。调研依据见 edit-routing-rules/research.md 及本次对 Zashboard、MetaCubeXD 连接/延迟/命中统计源码的检查。

## Goals / Non-Goals

实现用户确认的候选 1、2、3。备份历史、应用流量汇总、节点质量评分和 DNS 查询工具不属于本变更。

## Decisions

- 延迟记录包含 delay/time，手动探测在请求完成时记录时间与测试 URL；API 记录使用核心时间。相同数值的新时间必须视为新测量；轮询不得把旧结果刷新成“刚刚”。缺少时间显示未知，不伪造。合并按时间去重，保持最新手动结果，按目标切换清空。
- 测速参数优先使用核心返回值。本地 interval/lazy 仅从明确正在使用的原生配置读取；远程未知参数显示不可用，不使用本机文件补齐。lazy/interval 不表示确切下次运行时间。分组弹窗提供明确的“刷新数据”和“重新测速”。
- 解码 extra 的 hitCount/hitAt/missCount/missAt。原生文件与运行态完整匹配且来源是当前运行配置时才按原索引关联统计；离线或未应用文件显示不可用。排序只改变展示，不改变 YAML 顺序。重载后以核心最新值为准。
- 连接详情由根面板 sheet 承载。代理链沿连接原始链展示并明确与组当前选择的区别；节点/组详情可查看延迟、刷新、选择可选组成员。连接跳规则只使用类型与 payload 匹配，重复项列候选，不猜索引；单候选仍核对当前文档/运行态再打开原生编辑器，远程只读。
- 持久化数据仍为原生 YAML；诊断无写入。整份订阅更新仍可能覆盖用户编辑。原有保存校验、冲突、备份及重载流程不变。

## Risks / Trade-offs

旧核心字段缺失降级显示。核心统计随规则重载可能重置，不是流量总量；missCount 不是丢包。进程字段取决于核心 find-process-mode。已关闭连接仍保留当前详情快照，但不扩展为全局历史。

## Validation

模型测试覆盖时间合并、缺失字段、同值新测量、计数和元数据。视图模型测试覆盖原生/运行态关联、命中排序及重复规则候选。中英文浅深色渲染检查。真实核心仅独立临时目录/进程验证。运行 swift build、swift test、make spec-check、更新 CodeGraph 并打包。
