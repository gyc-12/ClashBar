## Context

主面板宽度来自 `MenuBarLayoutTokens.panelWidth`，AppKit 容器和 SwiftUI 视图共用该值。根视图测量头部、导航和页脚，按屏幕可用高度分配滚动区。列表页位于根视图的 ScrollView 中，编辑和诊断使用 sheet 或独立的节点弹出菜单。

已有提供商管理变更已单独提交并推送为 `0964441`。本次呈现层直接使用这些原生定义和运行摘要。

## Goals / Non-Goals

Goals：完整落地用户提供的五阶段 UI 计划；提高中英文可读性、信息层级和空间利用；浅深色一致；常用操作能通过鼠标、键盘和辅助功能访问；保留已有配置事务和控制功能。

Non-Goals：新增业务能力、改变 mihomo 配置结构、替换核心或系统代理 Helper、引入网页面板、网络字体、图片生成或第三方 UI 框架。

## Decisions

### 1. Shared design system

面板宽度 376pt，水平边距 12pt，区块间距 10pt，面板圆角 12pt，内嵌卡片圆角 10pt。紧凑按钮仍保留较小圆角，列表根据内容使用合适行高。

`Font.app` 使用系统字体和等宽数字；`Font.appMono` 用于端口、地址、路径、日志和原生规则预览。标题、节点和组名称使用系统字体。

卡片和控件通过视图环境读取外观，提供浅色柔白、深色微亮及减少透明度时的实色背景。共用图标底托、语义微标签和延迟胶囊。延迟按 `<150ms`、`150...350ms`、`>350ms` 分为绿、琥珀和珊瑚色；失败和未测量有独立文字与色调，不只依赖颜色。

### 2. Panel hierarchy and navigation

头部使用干净图标、运行状态点和带悬停背景的操作槽。模式为水平图标加文字的紧凑分段控件，页面导航使用图标、文字及填充选中背景，并提供辅助功能选中状态。

固定区块的间距纳入高度测量。代理和系统页继续按内容收缩，长列表页使用可用面板高度。过滤卡片通过 `LazyVStack` 的 section header 在同一滚动区置顶，避免嵌套整页滚动视图。规则统计、来源与编辑入口随内容滚动，仅筛选区和列头置顶，给短面板中的完整规则行保留空间。导航按标签自然宽度分配空间，确保英文 Connections 完整显示。屏幕最大高度仍由 AppKit 容器计算。

### 3. Proxy dashboard and progressive disclosure

节点页顶部默认仅显示单行紧凑流量条（实时下载 / 上传速率、连接数与内存，累计流量放在悬浮提示和辅助功能文案中），不默认展示波形图，把首屏空间留给提供商和策略组。系统设置页提供「显示流量曲线图」开关（默认关闭）；开启后在流量条下方展示平滑曲线。平滑插值使用单调三次曲线，限制控制点以避免突变样本造成负值或越界；最多显示最近 60 个点，并正确处理空历史和单点。

系统代理和 TUN 为双列磁贴，开关仍调用现有方法。TUN 协议栈收纳进菜单并沿用核心版本与忙碌状态限制；远程目标的本地系统代理范围仍明确展示。切换配置与复制终端代理命令收纳进系统设置页顶部卡片，减轻节点页首屏负担。

提供商卡片保留添加、启停、编辑、删除、加载状态和订阅用量。策略组常态显示名称、当前节点及延迟；测量时间和单组测速在悬停、键盘焦点或测速中显示，布局预留空间以避免跳动。弹出节点列表保留原顺序冻结、选中标记、历史与测速能力。节点菜单复用可单独渲染的 `AttachedPopoverSurface`，宽高均包含内边距，与 AppKit 外部面板尺寸一致。

### 4. Lists and settings

切换配置的附属弹窗也使用同一套分组卡片、图标底托、状态标签和紧凑开关。配置选择与管理操作分开，当前文件同时用勾选和浅底色标明；长文件名中间截断并支持查看全名。外层继续使用受屏幕约束的可滚动面板，订阅刷新与文件右键菜单仍独立于选择按钮，不更改原生配置或 Wi-Fi 绑定语义。

规则类型与网络协议使用语义标签；技术目标使用等宽字体，策略名称用系统字体。规则的原生索引、来源、命中与编辑操作保持可用。连接和日志采用分组列表，系统设置按基础设置、核心、端口和维护分卡片。

### 5. Modal structure

`ModalSheetContainer` 统一标题、图标、副标题、分隔线、可滚动内容和固定底部操作栏。表单字段共用分组卡片，表达式和路径使用自适应代码样式。快捷规则、原位规则、应用分流、提供商、连接详情和策略组诊断采用同一结构。保存中仍禁止关闭；错误、保存结果、备份与订阅覆盖提示保留。

### 6. Native file, runtime and overwrite boundaries

本次只调整呈现与交互布局。原生规则和提供商数据仍由主 YAML、原生 provider 文件及现有受管理注释决定；不增加持久化中间层。开关、测速、重载与保存沿用现有视图模型入口和事务锁。运行摘要不能替代未应用文件的状态。整份配置订阅覆盖的现有提示与处理继续保留。

## Risks / Trade-offs

376pt 宽度和更大间距可能使面板更高，因此必须按实际固定区块测量，并在短屏幕中滚动。中英文和长名称可能造成截断，需要在原生渲染中核对。悬停操作不能失去键盘或辅助功能入口。平滑曲线不能制造超出数据范围的峰值。卡片透明度必须在深色和减少透明度模式下保持可读。

## Validation

运行 `make graph` 并检查布局、根视图和代理页调用关系；执行 `swift build`、`swift test`、`make spec-check`。新增有意义的曲线边界、面板高度与中英文键一致性检查，复用配置和视图模型回归。视觉测试只使用临时目录、独立偏好与 loopback 的无服务目标，不启动或控制用户核心；导出所有页面、空状态、长名称与弹窗的中英文浅深色 PNG。真实核心协议没有变动，本次不以 UI 渲染代替核心业务验收。
