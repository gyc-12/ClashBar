---
title: 快捷添加分流规则
description: 从浏览器、分流、连接和日志直接保存原生 mihomo 规则
---

ClashBar 将规则直接保存到 mihomo 原生配置或已有的本地规则文件。同一份配置可以使用裸核心运行，无需 ClashBar 合并规则。

## 从哪里添加

- 面板顶部的网站规则按钮：读取打开面板前使用的浏览器当前网页。
- 分流页的 `+`：手动输入域名、IP、CIDR 或 HTTP(S) 网址。
- 分流规则、连接、mihomo 日志行的右键菜单：选择“添加分流规则…”，再选择目标。

浏览器支持 Safari、Chrome、Edge、Brave、Vivaldi、Opera、Chromium，及 Safari Technology Preview / Chrome Canary。首次读取会请求 macOS 自动化权限。权限拒绝、浏览器不支持、没有网页或打开内部页面时，可以在编辑器中手动粘贴网址。

连接同时提供域名和目标 IP 时，可以分别选择。日志只识别明确的连接目标，不会将整段日志里的所有域名、源地址都作为候选。

## 确认匹配范围

- `DOMAIN`：精确域名，默认选择。
- `DOMAIN-SUFFIX`：当前填写的域名及其子域名，不会自动扩大到上级域名。
- `IP-CIDR` / `IP-CIDR6`：IP 或网段。单个地址默认使用 `/32` 或 `/128`。

网址只保留主机，不保留端口、路径、查询参数和片段。保存前检查预览和目标策略。

## 保存到当前配置

默认写入原生 `rules` 顶部，相同类型与目标的旧规则会被替换为所选策略，其余规则保持原顺序。策略来自当前配置，包括 DIRECT、REJECT 和声明的策略组、节点。

新增规则带有 `# clashbar:custom` 注释，可在分流页的“自定义”筛选中查看。普通块格式 YAML 保留其他规则及注释；流式根映射或涉及跨字段锚点的特殊结构可能等价重新序列化。修改前会在目标文件旁保留隐藏备份，保存成功后可点击“在 Finder 中显示修改前备份”。

## 保存到已有本地规则集

“保存位置”也会列出满足以下条件的集合：

- `type: file`，格式为 `yaml` 或 `text`；
- `behavior` 为 `domain`、`ipcidr` 或 `classical`；
- 文件已经存在、可写，并位于 mihomo 工作目录内；
- 当前主配置的顶层 `rules` 已通过 `RULE-SET` 引用该集合。

集合的策略来自现有 `RULE-SET` 引用，不能在追加时另选策略。ClashBar 只追加兼容的条件并去重，不新建集合、不改变绑定或优先级。若较早的其他规则已命中目标，后面的集合不会覆盖该规则。

HTTP 下载缓存、MRS、未引用或不可写的集合不会提供写入入口。

## 校验与生效

保存前使用 mihomo 校验临时候选文件，原文件在校验通过后才被替换。运行中的主配置在核对文件与核心规则一致后通过 API 重载，本地规则集通过 API 刷新；核心未运行或文件与运行态不一致时，只保存文件，启动或切换到此配置后生效。该操作需要本地已安装的 mihomo 来校验。

新规则作用于新连接，不主动关闭已有连接。Global / Direct 模式下需要切换到 Rule 模式。

应用失败时尝试恢复原文件和运行状态。如果文件被外部程序修改，不会覆盖外部改动；若恢复未完成，错误信息会显示备份位置。

## 订阅更新与远程机器

整份订阅更新可能覆盖直接写入的规则，也可能移除本地规则集的引用。ClashBar 不会在更新后自动重新合并。长期维护自定义规则时，建议保留一份本地主配置，让 `proxy-providers` 更新节点订阅。

远程机器只有控制 API，无法通过通用接口安全持久化服务器文件，因此快捷规则编辑仅对本地配置开放。
