---
title: 原位编辑分流规则
description: 编辑每条原生规则、更换匹配策略并查看自定义规则
---

分流页读取当前选中的本地 YAML 配置，即使核心停止也能查看规则。每行显示原始序号；搜索、按类型筛选和按策略分组都不会改变配置中的实际顺序。

## 编辑与更换策略

点击行尾的铅笔，或右键选择“编辑规则”，可以修改规则类型、条件、策略及适用参数。点击策略名称直接打开可搜索的选择器，包含当前配置声明的隐藏代理组、节点和有效内置策略。选择新策略后保存此规则，不改变策略组内部选中的节点。

逐条编辑保持原来的位置，也不会去重。两个内容相同的条目按原始序号分别定位。修改前会校验候选、检查文件是否发生外部修改，并在文件旁保留隐藏备份；保存成功后编辑器提供 Finder 入口。

`MATCH` 没有匹配条件。`RULE-SET` 的策略影响该引用匹配的整个集合，不会修改 HTTP/MRS 下载缓存；单个域名的例外可以通过新增更靠前的原生规则处理。`SUB-RULE` 的目标选择器提供子规则名。逻辑表达式可以编辑条件，未知类型或无法可靠拆分的规则可切换到原文编辑，最终由 mihomo 校验。

## 自定义规则

“全部 / 自定义”筛选根据规则行的 `# clashbar:custom` 注释识别来源。快捷添加到主配置的新规则自动带标记。旧的无标记规则可以在编辑器中勾选“标记为自定义规则”。

标记只修改注释，不移动条目，也不提高优先级。移除注释或脱离 ClashBar 使用相同配置时，规则仍然由 mihomo 正常执行。整份订阅覆盖更新可能移除本地修改和标记，ClashBar 不在更新后隐式合并。

## 保存与连接行为

文件与当前核心规则对应时，通过 `PUT /configs?force=false` 在现有进程内重载，并保留核心当前的模式、端口和完整 TUN 设置。保存时确认目录监控基线，避免自身写入触发额外重启。只改变自定义标记时不发起核心重载。

核心停止、当前文件并非运行配置，或文件规则与运行态不一致时，只保存文件并显示“尚未应用”；启动或切换到此配置后生效。规则编辑仅对本地配置开放。

新规则用于后续连接，ClashBar 不主动清空已有连接。独立 mihomo v1.19.31 集成测试验证了 PID 不变、持续 TCP 连接继续传输、新 TCP 连接按新策略处理。配置重载仍有暂停处理的窗口，新的请求可能短暂失败，UDP 包可能丢失。Global / Direct 模式下需要切回 Rule 才能按分流规则处理。

应用失败时恢复原文件，并尝试恢复运行态。如果恢复期间发生外部修改，保留外部内容并提示备份路径。
