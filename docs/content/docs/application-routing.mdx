---
title: 按应用设置分流
description: 选择应用或连接进程，保存原生 mihomo 进程规则
---

ClashBar 将应用分流保存为主配置中的原生 `PROCESS-PATH` 或 `PROCESS-NAME` 规则。同一份配置可以脱离 App 使用 mihomo 运行。

## 从哪里打开

- 分流页右上角的应用图标：“按应用设置分流”。
- 连接行右键：“为此进程设置分流…”。
- 连接详情的进程信息下方：“为此进程设置分流…”。

连接入口只有在核心提供有效进程名或绝对路径时出现。远程机器的本地应用规则编辑不可用。

## 选择应用和匹配方式

“已安装应用”按需扫描 `/Applications`、`~/Applications` 和 `/System/Applications`，支持搜索应用名称、实际进程名和路径。文件夹按钮可以选择其他位置的 `.app`。下方文本框也可手动输入。

“已观测进程”来自打开编辑器时保留的连接记录，不是完整系统进程列表。没有记录时，可先在连接页观察目标应用，再重新打开编辑器。

- **精确可执行路径**：默认方式，对应 `PROCESS-PATH`。只匹配指定可执行文件，应用迁移或更新后需要核对路径。
- **精确进程名**：对应 `PROCESS-NAME`。匹配实际可执行文件名称，其他同名程序也可能命中。

应用显示名可能与可执行文件名不同。选择 `.app` 时使用它的主可执行文件；浏览器等应用的 Helper 不自动包含在规则里，可以从连接页为这些进程单独添加规则。

## 选择策略和确认预览

策略按钮支持搜索，包含当前配置中的 DIRECT、REJECT、节点和代理组（包括隐藏组）。预览展示即将保存的完整原生规则，例如：

```yaml
rules:
  - 'PROCESS-PATH,/usr/bin/curl,开发组' # clashbar:custom
  - 'MATCH,DIRECT'
```

保存时规则置顶，同类型、同条件的旧规则被替换；其他规则保持原顺序。新增项可在分流页“自定义”筛选中查看，之后通过原位规则编辑器调整策略。

## 进程识别和生效

编辑器显示配置文件和当前有效运行设置中的进程识别模式。`off` 会禁止进程识别，编辑器会勾选可见的“同时保存并启用进程识别（strict）”；取消后不能保存无效规则。确认保存会将 `find-process-mode: strict` 写入原生配置，并用于当前配置的进程内重载。

其他运行设置继续保持，包括端口、TUN、IPv6、并发和当前模式。进程识别还依赖核心的运行权限；本机 macOS 上无权限的核心可能返回 `process not found`，即使 strict 已开启也无法匹配。该操作不修改核心权限或自动开启 TUN。规则只作用于进入核心的流量；Global / Direct 模式下应切换到 Rule 模式。

保存使用临时候选校验、修改前备份和原子替换，失败时尝试恢复原文件及运行态。检测到外部修改时拒绝覆盖，需重新打开编辑器。成功后可查看备份位置。

核心运行且文件与当前核心规则一致时，通过 API 在现有核心进程内重载；核心停止或编辑的不是当前运行配置时，仅保存文件，界面明确显示尚未应用。保存仍需要本地安装 mihomo，以进行校验。

新规则作用于后续连接，不主动关闭已有连接或重启核心。配置重载窗口的流量行为由核心决定，不能据此保证所有协议绝对无中断。

## 订阅覆盖

整份订阅更新可能移除应用规则和进程识别设置。ClashBar 不做隐式重新合并；长期维护时，建议保留本地主配置，通过 `proxy-providers` 更新节点订阅。
