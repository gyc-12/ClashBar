## 延迟是什么时候测的

代理组及节点的延迟旁显示测量年龄。时间来自核心历史记录，手动测速使用请求完成时间；“刷新显示数据”只读取核心，不把旧测量改成刚刚测得。核心未提供时间时显示“时间未知”。

展开代理组后，点击右上角 ⓘ 进入详情，可查看测试 URL、配置检测间隔、lazy 状态。点击节点延迟展开最近 4 条历史及时间；手动测速记录还会显示请求的测试 URL。已知间隔时超过两倍间隔（至少 60 秒）提示“较旧”；间隔未知时使用 10 分钟作为展示提示，这不是断言节点不可用。

interval 是配置检测间隔，lazy 可以推迟未使用节点的检测，不能由此推算准确的下一次测速时间。url-test 等自动组由核心检测，即使关闭面板仍按核心配置运行。只有核心返回或明确对应当前运行配置的本地参数才会显示；远程参数缺失时显示未知。

“重新测速”会主动触发探测。mihomo 对 URLTest/Fallback 等自动分组重新测速时会清除手动固定选择并恢复自动选择；刷新显示数据不会进行此操作。代理组详情可切换支持选择的分组成员。

## 规则有没有实际用到

分流页的“命中”列显示核心提供的次数及最近命中年龄。悬停可查看完整的命中/未命中次数和时间，以及规则集条目数。右上角箭头切换按命中次数排序和原始顺序，排序不会改写 YAML 或改变规则优先级。

本地文件必须与当前核心规则完整对应，才能按原始位置关联统计。核心停止、文件尚未应用、选中了其他配置或核心未提供统计时显示不可用，不将未知计数显示成零。统计来自当前运行态，规则重载后可能重置；命中次数不是流量大小，未命中次数不是丢包率。

点击刷新图标读取最新规则数据；右键刷新图标选择“更新所有规则集”，保留原有主动更新规则集的入口。

## 为什么这个请求走了这个节点

点击连接行，或右键选择“连接详情”，查看目标域名、嗅探域名、源/目标 IP 与端口、传输协议、DNS 模式、进程及路径、流量、入站、命中规则和代理链。进程字段是否存在取决于核心和 find-process-mode。连接离开当前保留列表后，详情使用打开时的快照，并明确标注。

代理链是这条连接实际经过的路径。点击链中的代理组可以查看它当前的选择及节点延迟；切换组成员通常只影响后续连接，已有连接的路径可能与组当前选择不同。

点击“查看命中规则”：若只有一个能对应当前原生配置的候选，进入已有规则编辑器；存在重复匹配项时，先显示候选列表，按原始序号选择。核心没有精确规则索引时，不猜测是哪一条重复规则。本地配置尚未对应运行态或连接属于远程核心时，候选规则保持只读。

查看诊断不写配置，也不重启核心。保存规则仍走原生 YAML 校验、备份、冲突检测和现有进程内重载流程，详见[原位编辑分流规则](/docs/routing-rule-editor)。
